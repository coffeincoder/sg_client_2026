# Доводка редизайна: вкладки + переработка панели зон

> **Для исполнителя:** РЕКОМЕНДУЕМЫЙ СУБ-НАВЫК: `superpowers:subagent-driven-development`
> или `superpowers:executing-plans` — исполнять задачами по очереди. Шаги отмечать `- [ ]`.
> Проверка UI — навыком **qt-testing** (offscreen-снимки). ВАЖНО: тестировать и на
> **минимальном окне** (1300×700), и на большом — баги прячутся на разных размерах.

**Goal:** Довести UI-редизайн клиента до мержа (фикс вкладок) и переработать панель зон
в раскрывающуюся область, чтобы она не занимала место на экране постоянно.

**Architecture:** PyQt5 QtWidgets. Общий стиль — `src/ui/theme.py` (QSS + токены).
Главное окно собирается в `src/ui/root/UI_MainWindow.py`. Проверка — offscreen-снимки
через `.claude/skills/qt-testing`.

**Tech Stack:** Python 3.12, PyQt5, venv в `sg_client_2026/.venv`.

## Global Constraints

- 🔴 **Fleet-compat:** ~100 клиентов в поле. НЕ переименовывать ключи протокола/MQTT/JSON
  (`command/filename/filesize/crc/value/button/…`). Внутренние имена методов/переменных —
  свободно. См. `COMPATIBILITY.md`.
- 🔴 UI: без эмодзи, только PNG-иконки из `res/IMAGES`; крупные контролы (пожилые дежурные).
- Запуск клиента: `cd sg_client_2026 && .venv/bin/python main.py`. Если «Приложение уже
  запущено» → `rm app_lock.txt` (lock блокирует только полный запуск, не offscreen-снимки).
- Ветка работы: `feature/ui-redesign`. Коммиты локальные, пуш — по явной просьбе.

### Task 1: Вкладки «Файлы»/«сценарии» — убрать обрезку первой буквы

**Причина (продиагностировано):** QSS `QTabBar::tab { font-weight: 600 }` делает текст
жирным, но Qt резервирует ширину таба по НЕ-жирным метрикам → жирный текст шире и
обрезается (у «сценарии» срезается «с» слева).

**Files:**
- Modify: `src/ui/root/UI_MainWindow.py` — метод `_build_file_list_panel` (создание `tab_widget`)
- Modify: `src/ui/theme.py` — правило `QTabBar::tab` (padding)

**Interfaces:**
- Consumes: существующий `tab_widget = QtWidgets.QTabWidget(self.central_widget)` в конце
  `_build_file_list_panel`.
- Produces: ничего нового (визуальная правка).

## ЧАСТЬ B. Переработка панели зон (СНАЧАЛА брейншторм)

> ⚠️ Это отдельная фича с непринятым дизайн-решением. НЕ начинать с кода.
> НАЧАТЬ с навыка `superpowers:brainstorming`, затем `superpowers:writing-plans` для отдельного плана.

**Проблема владельца:** панель «Зоны-Устройства» всегда на экране и занимает место.
Хочется вынести её в отдельное окно ИЛИ (предпочтительно) в раскрывающуюся область,
которую открывают для настройки.

**Что учесть при брейншторме (контекст для будущей сессии):**

- Зоны несут ДВЕ функции: (1) живой статус (онлайн/офлайн/играет) — нужен постоянно;
  (2) настройка (добавить/переименовать/удалить/подзоны/громкость) — эпизодически.
  Полностью прятать статус рискованно для дежурного.
- Виджеты уже есть: `ZoneListWidget` (`src/ui/custom/zone/ZoneListWidget.py`),
  `ZoneListItem`. Кнопки/панель собираются в `UI_MainWindow._build_zone_panel`
  (`zone_list_container`), встраиваются в правую панель в `_assemble_main_layout`
  (`right_widget`). Данные — `ZoneItemRepository`; обновления статуса идут в
  `main.py` (`orange_status_receiver`, `update_zones`) → менять их СИГНАТУРЫ нельзя без нужды.

**Варианты (обсудить с владельцем, выбрать один):**

- **Вариант A — сворачиваемая правая панель (drawer).** Кнопка-переключатель в шапке
  сворачивает `right_widget` в тонкую полосу/прячет, освобождая место списку файлов.
  Плюс: статус остаётся под рукой одним кликом. Минус: в свёрнутом виде статус не виден
  (можно оставить компактные индикаторы-точки на полосе). *Рекомендуется как база.*
- **Вариант B — отдельное окно настройки зон.** Основное окно показывает компактный
  статус-бар зон; полноценное управление — в `QDialog`/отдельном `QMainWindow` по кнопке
  «Настроить зоны». Плюс: максимум места файлам. Минус: статус нужно продублировать компактно,
  больше кода, синхронизация двух представлений.
- **Вариант C — гибрид.** Компактная полоса статуса всегда видна + раскрытие в drawer или
  диалог для настройки. Больше всего работы.

**Первые шаги будущего плана (после выбора варианта):**
1. `superpowers:brainstorming` — выбрать A/B/C, определить: что видно в свёрнутом виде,
   где кнопка-переключатель, сохранять ли состояние (свёрнуто/развёрнуто) между запусками.
2. `superpowers:writing-plans` — отдельный план `docs/superpowers/plans/YYYY-MM-DD-zones-<вариант>.md`
   с TDD-задачами, проверкой через qt-testing на мин/макс окне и обязательным реальным запуском.
3. Обязательно: не трогать протокол/сигнатуры обновления статуса; проверить на минимуме окна.
