# Дизайн: 8 каналов (двухуровневая модель) в окне и панели зоны

**Дата:** 2026-08-25
**Статус:** дизайн согласован, готов к плану
**Основа:** ветка `feature/zone-8-channels` (от `feature/zone-4-channels`)
**Предыдущий спек:** `2026-08-16-zone-4-channels-design.md` (эта работа его развивает)

## 1. Задача

Развить фичу каналов с 4 до **8** и перейти на **двухуровневую модель** (по требованию sun0):
- **Окно добавления/редактирования устройства:** галочками выбираешь, *какие каналы есть у устройства* (из 8) + вводишь их имена.
- **Панель (список устройств):** показываются **только эти** каналы, каждый **галочкой** с именем — оператор выбирает, *в какие вещать сейчас*.

Это отменяет решение прошлой итерации «в панели — подписи»: теперь в панели снова **интерактивные галочки**, но с чётким двухуровневым смыслом.

## 2. Картина железа (контекст, НЕ наша реализация)

«8 каналов» = 2 источника × 4 линии:
```
Каналы 1–4  →  Orange, реле out1..out4  (сдвиговый регистр)   ← сделано в прошлой итерации
Каналы 5–8  →  ESP32,  реле rel1..rel4  (команды 'rel1 0'/'rel1 1' по проводу)
```
**Серверная часть (маршрутизация, ESP32, коммутатор) — зона sun0** (коммит `e2f8a93`: он добавил `rel1..rel4` в `ESP32Commands` и построил на нашем `parse_play_variant`). Мы серверный код не пишем.

## 3. Двухуровневая модель — суть

На каждый канал две независимые сущности:
- **present** — «канал есть у устройства» (задаётся галочкой в окне);
- **active** — «канал активен для вещания сейчас» (задаётся галочкой в панели).

Панель показывает только `present`-каналы; среди них оператор отмечает `active`.

## 4. Данные (`src/data/ZoneModel.py`, `ZoneItemRepository.py`)

Расширяем dataclass `Orange` (новые ключи только добавляем — совместимость флота):
- `subzone1..8` (bool) — **active** (для 1..4 поле уже есть, добавляем 5..8);
- `subzone1..8_name` (str) — имя (5..8 добавляем);
- `subzone1..8_present` (bool) — **present**, все 8 новые.

Репозиторий читает все новые поля через `.get(..., дефолт)` во всех местах, где строит `Orange` из словаря.

## 5. Окно добавления/редактирования (`src/ui/fragments/UI_AddZoneWindow.py`)

- 8 строк **вертикально**: `QCheckBox("Канал N")` (= present) + `QLineEdit` (имя).
- Поле имени активно, когда галочка present стоит; иначе серое.
- `get_channels()` возвращает 8 пар `(present, name)` в порядке 1..8.
- Валидация: нельзя сохранить устройство с **0 present-каналов** (предупреждение).
- Окно задаёт `present` + `name`. Правило для `active` при сохранении окна:
  - канал **стал** present (создание устройства или впервые отметили) → `active = True` (дефолт №1);
  - канал **был и остаётся** present → `active` не трогаем (им владеет панель);
  - канал **перестал** быть present (сняли галочку) → `active = False` (канал исчезает из панели).

## 6. Панель (`src/ui/custom/zone/ZoneListItem.py`)

- Для каждого `present`-канала рисуем **чекбокс** с подписью `subzoneN_name or f"Канал {n}"`, **вертикально**.
- Галочка = `active`; изменение сохраняется в `zones.json` (все 8 `subzone*`/`_present`/`_name`).
- Не-present каналы не показываются.
- Большой чекбокс всей зоны (`isChecked`) остаётся.

## 7. Протокол (`src/viewmodel/playback_viewmodel.py`, `channel_utils.py`)

- `active_channels(zone)` расширяем на 1..8: номера, где `subzoneN` (active) **и** `subzoneN_present`.
- `format_play_variant` без изменений — строка через запятую, например `"1,5,7"`.
- Формат остаётся **строкой** (не массив) — согласовано с sun0.

## 8. Миграция (флот ~100 клиентов, старый формат из 2 подзон)

Старый `zones.json` грузится так:
- `subzone1_present = True`, `subzone2_present = True` (у старых устройств эти каналы были);
- `subzone3..8_present = False`;
- `subzone1/2` (active) и имена — как в файле; `subzone3..8` → `False`, имена → `""`.

Никто не теряет свои каналы. Существующие ключи `subzone1/subzone2/subzone1_name/subzone2_name` **не переименовываем**.

## 9. Выбранные дефолты

1. **Новый present-канал по умолчанию active** (добавил канал → он сразу вещает, пока не снимешь в панели). Безопаснее для оповещения.
2. **Минимум 1 present-канал** у устройства (валидация в окне).
3. **Имена каналов остаются** (sun0 просил показывать имена).
4. **Активный выбор в панели запоминается** между запусками (как сейчас).

## 10. Что НЕ входит в нашу работу

- Серверная маршрутизация, ESP32 (`rel1..rel4`), коммутатор — sun0.
- Смена формата на массив — НЕ делаем (остаётся строка).

**Что мы берём и на серверной стороне:** расширить `parse_play_variant` с 1..4 до **1..8** + тесты на каналы 5–8. Это наш файл, правка в одну строку. Делаем в серверном репо `sg_orange_2026-` **поверх свежего коммита sun0 `e2f8a93`** (сначала подтянуть его), и предупредить sun0, что трогаем `play_variant_parser.py`.
