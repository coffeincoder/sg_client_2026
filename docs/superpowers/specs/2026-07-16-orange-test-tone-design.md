# Диагностический тон (1 кГц) на Orange по горячей клавише — дизайн

**Дата:** 2026-07-16
**Затрагивает два репозитория:**
- `sg_orange_2026-` (прошивка Orange Pi) — **основная реализация**, ветка своя.
- `sg_client_2026` (клиент PyQt5) — **только команда**, ветка от `refactor/mainwindow-mvvm`.

**Статус:** дизайн на утверждении владельцем, план ещё не написан.

> **Масштаб:** это **отладочное удобство** для железячника (Андрея), который по
> синусоиде смотрит импеданс/сопротивление линии. Не боевая фича — намеренно
> минимум церемоний: без сложной обработки краёв, без богатой деградации, без
> тяжёлых тестов. Главное — чтобы было удобно и не мешало обычной работе.

## Цель

Дать инженеру (Андрею) быстрый способ подать непрерывный тон на линию
оповещения для диагностики: нажал `Ctrl+Shift+T` — на выбранных зонах
Orange заиграл синус 1 кГц; нажал ту же комбинацию ещё раз — тон прекратился.

Тон нужен как **синтезированный сигнал**, а не проигрывание файла: стабильная
частота для измерений, без управления файлом-активом.

## Ключевые решения (зафиксированы в brainstorm)

1. **Куда шлём:** только зоны с `isChecked` (как обычное воспроизведение) — безопасно,
   не зазвучит лишняя линия в рабочем здании.
2. **Способ:** синтез тона **в прошивке Orange** (генерация PCM на лету, вывод через
   pyaudio), а не файл и не RTP-стрим с клиента.
3. **Toggle:** отслеживается **на клиенте** (флаг + выбор `test_tone`/`stop`).
   Прошивка проще: `test_tone` = старт, `stop` = стоп.
4. **Частота:** настраиваемая, берётся из **конфига клиента** (дефолт `1000` Гц),
   без UI-поля. Прошивка принимает любую частоту параметром.
5. **Громкость:** текущая (значение `volume_slider`), как у обычного play.
6. **Клавиша:** `Ctrl+Shift+T` (первый `QShortcut` в проекте).

## Протокол (новый additive-ключ)

Клиент → Orange, старт тона:
```json
{"command": "test_tone", "freq": 1000, "vol": 63}
```

Стоп **переиспользует существующую команду** (не плодим `stop_tone`):
```json
{"command": "stop"}
```

- `test_tone` — **новый добавляемый** ключ. Существующие команды/ключи не переименовываем
  → жёсткое fleet-ограничение не нарушается (см. [[ksb-fleet-compat-constraint]]).
- Ответы Orange:
  - успех — `"Tone playing"`;
  - занято (`is_playing`/`is_streaming`) — busy-ответ, как у `play`;
  - **старая прошивка** ключа не знает → ответа нет / таймаут. Для debug-инструмента
    отдельной обработки не делаем: клиент просто не падает (см. «Ошибки»).

## Прошивка Orange (`sg_orange_2026-`) — основная реализация

Файлы: `sg_main.py` (`CommandHandler.handle`), `ServerState.py` (аудио).

- Новая ветка `elif data["command"] == "test_tone":` в `CommandHandler.handle`.
  - Читает `freq` (int, Гц) и `vol` из запроса.
  - **Гард:** если `is_playing` или `is_streaming` — вернуть busy, тон не стартовать
    (ALSA-устройство одно, одновременно с обычным воспроизведением нельзя).
  - Иначе запустить поток синтеза, ответить `"Tone playing"`, выставить флаг активности
    тона.
- Синтез в `ServerState`:
  - Открыть pyaudio output ровно с теми же параметрами, что `play_realtime`
    (`paInt16`, `44100`, mono, `output_device_index=0`).
  - Сгенерировать **буфер ровно 1 секунда** (`sample_rate` сэмплов) синуса частоты
    `freq`. Для целой частоты в Гц это целое число периодов → буфер **зацикливается
    бесшовно сам собой**, без возни с переносом фазы.
  - Цикл: писать этот буфер в stream, пока не поднят стоп-флаг.
- Остановка: расширить `stop_any_playback` — помимо `killall aplay`:
  поднять стоп-флаг тона, дождаться завершения потока, закрыть pyaudio stream,
  сбросить флаг. Существующая команда `stop` уже вызывает `stop_any_playback`,
  поэтому отдельная стоп-команда не нужна.
- Чистая функция-генератор (тестируемая без железа), напр.:
  `sine_buffer(freq: int, sample_rate=44100) -> bytes` — возвращает 1 секунду
  int16 PCM.

## Клиент (`sg_client_2026`) — только команда

Ветка от `refactor/mainwindow-mvvm`. Изменения минимальны.

- **Конфиг-константа частоты** (дефолт `1000`), в существующем конфиге клиента.
- **`OrangeWorkerTCP`:** новая ветка `test_tone` — шлёт
  `{"command":"test_tone","freq":<freq>,"vol":<vol>}`. **Без загрузки файла**
  (ключевое отличие от `play`: `load_file` не вызывается).
- **`PlaybackViewModel`** (он уже владелец orange-команд — избегаем cross-VM связей):
  - флаг `is_tone_playing` (client-side toggle);
  - метод `toggle_test_tone()`:
    - если не играет → `commit_orange_command("test_tone", freq=<конфиг>, vol=<текущая>)`
      на checked-зоны; поднять флаг;
    - если играет → `orange_stop()` на checked-зоны; сбросить флаг.
- **`QShortcut(QKeySequence("Ctrl+Shift+T"), MainWindow)`** → `vm.playback.toggle_test_tone()`.

## Поток данных

`Ctrl+Shift+T` → `PlaybackViewModel.toggle_test_tone()` → по флагу
`test_tone` **или** `stop` → `OrangeWorkerTCP` на каждую checked-зону →
Orange `CommandHandler` → старт/стоп потока синтеза (pyaudio).

## Ошибки (минимально, это debug-инструмент)

- **Старый Orange не знает `test_tone`:** ответа нет / таймаут — клиент просто не
  падает, отдельного UX не делаем (Андрей знает, где стоит новая прошивка).
- **Флаг клиента разошёлся с реальностью** (перезапуск и т.п.): страховка — обычная
  кнопка **Stop** глушит тон тоже (через `stop_any_playback`).
- **Зона занята обычным воспроизведением:** busy-ответ, как у `play` (гард на прошивке
  не даёт тону влезть поверх реального оповещения).

## Тестирование (лёгкое)

- **Прошивка:** один юнит-тест чистой функции `sine_buffer` — корректная частота,
  формат int16 PCM, длина = 1 сек. pyaudio-вывод на железе локально не тестируется
  (analysis-only, см. [[ksb-server-analysis-only]]).
- **Клиент:** ручная проверка (шорткат шлёт `test_tone`/`stop`, файл не грузится).
  Автотесты не обязательны — фича маленькая и изолированная.
- **End-to-end (реальный звук на линии):** проверяет Андрей на железе.

## Объём, ветки, порядок

- **Один spec** на оба берега (этот файл). Реализация — двумя ветками в двух репозиториях.
- Порядок в плане: **сначала прошивка** (`test_tone` + генератор + юнит-тест),
  затем клиент (worker + VM-toggle + шорткат + деградация).
- Клиентская часть стоит на `refactor/mainwindow-mvvm`; после её слияния в `dev` (шаг A5)
  ляжет естественно.

## Не входит в объём (YAGNI)

- UI-поле выбора частоты на клиенте (только конфиг).
- Несколько одновременных частот / развёртки / свипа.
- Управление тоном на ESP32-устройствах (только Orange Pi).
- Генератор тона в прошивке как новый ключ у ESP32.
