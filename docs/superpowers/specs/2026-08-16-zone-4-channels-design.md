# Дизайн: 4 канала в окне зоны

**Дата:** 2026-08-16
**Статус:** дизайн согласован, готов к плану
**Затрагивает:** `sg_client_2026` (клиент) + `sg_orange_2026-` (сервер)

## 1. Задача

Расширить окно настройки зоны (открывается по кнопке «+ зона», класс `UI_AddZoneWindow`, заголовок «Настройка зоны оповещения») с **2 до 4 «каналов»**. У каждого канала:
- чекбокс активности;
- поле имени канала.

Поведение: **чекбокс включён → поле имени активно; выключен → поле серое/заблокировано.** В панели зоны (список зон) пользователю показываются **только активные каналы**.

Источник ТЗ — макет (фото) от разработчика: поле названия зоны, поле IP, блок «Чекбоксы активности канала» с Канал 1–4, кнопки Отмена/Создать. Выбора источника звука в макете нет.

## 2. Термины (уточнено разработчиком 2026-08-16)

У разработчика точная терминология отличается от бытового «канал»:

| Термин | Что это | Сколько |
|---|---|---|
| **Канал** | *источник* звука (Orange или ESP32) | 2 |
| **Линия** | *приёмник* звука (громкоговоритель), включается через реле `out1..out4` | 4 |

Но и в макете, и на подписях лампочек разработчик сам зовёт 4 линии «каналами». Поэтому:
- **в UI оставляем подпись «Канал 1–4»** (совпадает с макетом, лампочками, текущим кодом и ключами JSON);
- внутри помним: **«Канал N» в интерфейсе = физическая линия `outN`** (маппинг 1:1, подтверждён разработчиком).

**Источник** остаётся всегда Orange (как сейчас, `orange_to_both_channel`). Выбор источника оператору не показываем — в макете его нет. Если понадобится позже — это отдельное *добавление*, текущую работу не ломает.

## 3. Изменения по слоям (клиент)

### 3.1 Данные — `src/data/ZoneModel.py`, `ZoneItemRepository.py`
Добавить **новые поля с дефолтами** (не переименовывать существующие — совместимость флота, ~100 клиентов):
- `subzone3: bool = False`, `subzone4: bool = False`
- `subzone3_name: str = ""`, `subzone4_name: str = ""`

В `ZoneItemRepository` читать их через `.get("subzone3", False)` и т.д. — старые `zones.json` без этих ключей грузятся как «выключено» (migrate-on-load).

### 3.2 Окно — `src/ui/fragments/UI_AddZoneWindow.py`
- 4 строки «канал» вместо 2: у каждой **чекбокс активности + поле имени**.
- Связать чекбокс с полем: `checkbox.toggled → field.setEnabled(...)`. Выключен → поле серое.
- Отдать наружу состояние всех 4 каналов (флаги + имена).

### 3.3 Панель зоны — `src/ui/custom/zone/ZoneListItem.py`
- Показывать **только активные каналы** (по их именам). Сейчас всегда рисуются 2 чекбокса подзон — переделать на отрисовку активных из 4.

### 3.4 Протокол воспроизведения — `src/viewmodel/playback_viewmodel.py` + `src/network/OrangeWorkerTCP.py`
- Вместо строки-комбинации (`channel_1`, `channel_1_2`, …) собирать **список активных линий** и слать его.
- Формат: `{"command": "play_variant", "value": "1,3,4"}` — номера через запятую, пусто `""` = ни одного канала.
- **Заодно фикс бага:** в текущем `playback_viewmodel.py` (~строка 125) ветка `no_channel` проверяет `subzone2` дважды вместо `subzone1`.

## 4. Изменения на сервере (`sg_orange_2026-`)

Пишем сами, разработчик тестирует на Orange Pi (локально железа нет).

- **Разбор нового формата** в `ServerState.py` и `sg_new.py`: `value.split(",")` → список номеров → в цикле `outN(n in active)`.
- **Совместимость:** сервер продолжает понимать старые строки `channel_1`, `channel_2`, `channel_1_2` (для необновлённых клиентов). Не удаляем — дополняем.
- Реле `out3`/`out4` уже есть в `Digital_out_block` (сдвиговый регистр), распаяны. Сейчас логика «играть» включает только `out1`/`out2` — добавить 3/4.
- **Лампочки:** 8 шт, первый ряд = каналы 1–4. В коде заведены только 2 (`zone1_led`→`led4`, `zone2_led`→`led3`) — при желании единообразия дописать `zone3_led`/`zone4_led`. Второй ряд (Питание/Авария/Сбой/АКБ) не трогаем.
- **Причесать при правке:** в `ESP32Commands.py` `mic_led_on` объявлен дважды; sync-методы шлют `led3/led4`, async — `led1/led2` (несовпадение).

## 5. Валидация и крайние случаи

- **Минимум 1 активный канал:** при сохранении зоны без единой галочки — предупреждение «Выберите хотя бы один канал». (Защита пожилого дежурного от «немой» зоны; правило см. UI design rules.)
- **Сервер защищён от пустого ввода:** даже если прилетит пустой список — не падать, просто ничего не включать (тишина).
- **Порядок раскатки:** на объекте обновлять блок Orange и клиент вместе, чтобы новый клиент не попал на необновлённый сервер.
