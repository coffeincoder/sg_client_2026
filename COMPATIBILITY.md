# Чек-лист совместимости — проверь перед каждым merge

~100 клиентов работают на разных версиях. Одно неосторожное переименование
ключа — и часть устройств перестанет общаться с сервером.

---

## 🔴 НЕЛЬЗЯ переименовывать (сломает флот)

Ключи команд в сетевом протоколе (TCP/MQTT) — используются клиентом И сервером:

| Ключ | Где используется |
|------|-----------------|
| `command` | все команды |
| `filename` | передача файлов |
| `filesize` | передача файлов |
| `crc` | проверка целостности |
| `value` | команды управления |
| `button` | события кнопок |

Правило: **не переименовываешь — не ломаешь.**

---

## 🟡 JSON-файлы данных — только через migrate-on-load

Если меняешь ключ в `.json`-файле данных (настройки, сценарии, зоны):
1. В коде читай **оба** ключа: старый и новый.
2. При записи используй только новый.
3. Это позволяет старым клиентам подняться и автоматически мигрировать данные.

Пример:
```python
# Правильно — читаем оба:
name = data.get("zone_name") or data.get("name")
# Неправильно — только новый (старые клиенты не поднимутся):
name = data["zone_name"]
```

---

## 🟢 Можно переименовывать свободно

- Локальные переменные внутри функций
- Имена методов и классов (внутренние, не часть протокола)
- Имена Python-модулей (если обновляешь все импорты)

---

## Как использовать

Перед `git merge` (или открытием PR) пробегись по этому файлу:
- [ ] Я не переименовывала ключи протокола/MQTT?
- [ ] Если меняла JSON-ключи — добавила migrate-on-load?
- [ ] Изменения внутренние (переменные/методы) — ок без проверки?
